# ReadTrace: 本と映画の記録

本と映画の記録アプリです。実データ検索、ゲストの端末内保存、Google認証後のSupabaseクラウド保存に対応しています。公開版で実Googleログイン・クラウド保存と復元・共有先への認証復帰を確認済みです。既存の静的HTMLとNodeサーバーを継承し、フロントエンドのインストールやビルドは不要です。実装状況と残作業は `outputs/production-status.md` を参照してください。

## 起動

Node.js 20以降で、リポジトリのルートから実行します。

```powershell
npm start
```

http://127.0.0.1:8011/reading-prototype.html を開いてください。ポートを変更する場合は、PowerShellで `$env:PORT=8012` を設定してから起動します。

## 操作

- Googleログインは有効化済みです。実際のSupabaseプロバイダー設定を自動確認するため、フロントエンドに秘密情報を追加する必要はありません。Google側の公開ステータスとブランド整備の残作業は `outputs/production-status.md` を参照してください。
- 「ゲストで始める」では空の棚から実検索・登録・記録を利用できます。ゲストは端末内保存、Googleログイン後はクラウド保存です。旧データは自動削除せず、ログイン後に取り込む棚を選べます。
- 「デモを試す」から青山しおり・佐々木遥・森健太の棚を開けます。パスワードは不要です。デモ用の新規登録は表示名だけで空の棚を作ります。
- 本／映画タブ、状態フィルター、棚の検索と並べ替えを利用できます。
- 「作品を追加」で実際の書名・著者名・ISBNを検索します。国立国会図書館サーチとOpen Libraryを優先し、両方で作品が見つからない場合だけGoogle Booksを使用します。書影・概要の不足や、検索結果の最終ページだけを理由にGoogleへ追加取得しません。映画はApple iTunesを検索し、見つからない場合はWikidataの映画情報で補完します。不一致時は検索語を手入力に引き継ぎます。
- 「本を探す」には小説・ビジネス・ミステリー・SF/ファンタジー・歴史・刊行年が新しい本など、APIから取得するセクションがあります。人気順を保証できないデータをランキングとは表示しません。
- 作品を開くと、状態・0.5刻みの評価・任意の感想と日付・ネタバレ・公開範囲を編集できます。評価は5つの星を直接選択します。星の左半分は0.5刻み、右半分は整数値で、キーボードの矢印でも選択できます。「未評価」で解除でき、完了記録は評価必須です。
- プロフィールと公開棚、フォロー、みんなの記録、いいね、コメント、削除確認、URL共有を操作できます。
- アカウントメニューからデモユーザーの切り替えとログアウトができます。右上のアバターまたはスマホ下部の「自分」から開きます。月間読書目標と実績も利用できます。

UI PocketのApple Books掲載画面を参考に、表紙中心の棚・進行中作品の横並び・スマホ下部の追加ボタンを採用しています。参考と確認内容は `outputs/ui-redesign.md` に記載しています。

本の棚は緑、映画の棚は赤のテーマです。初期表示はグリッドで、表示設定は保存されます。スマホでは表示切り替えから表紙を横にドラッグして選べる立体棚にでき、回転ボタンで表紙を一周回せます。Three.jsを同梱しており、WebGLが利用できない場合は一覧へ戻ります。

## 保存と共有

記録・設定・交流は `readtrace:books-films:v2`、デモログインは `readtrace:demo-session:v2` に保存されます。旧版の保存データは変更しません。

非公開記録は本人以外の一覧・詳細・共有から除外します。公開記録でも閲覧にはデモログインが必要です。共有URLの遷移先はログイン後も維持されます。ネタバレ本文は一覧・共有プレビューに出ず、他ユーザーの詳細では操作するまで表示しません。

Google認証後は `readtrace_records` などのSupabaseテーブルを使用し、本人かログイン済みユーザーの公開記録だけをRLSで取得できます。共有先もGoogle認証が必須です。フォロー・いいね・コメント・目標もクラウド保存します。Realtimeと再読み込みで同期し、クラウド書き込みが失敗した場合にローカル保存を成功扱いすることはありません。同じ実Googleアカウントでの保存・更新・再読み込み・別タブ復元は確認済みですが、PCとスマホの二実機での同期は未確認です。

デモユーザーの記録は引き続きブラウザ上のモックです。ゲストは `readtrace:guest:v1` に保存し、共有にはGoogleログイン後の取り込みが必要です。以前の `readtrace:account:<auth-user-id>:v1` を含む元データは残します。デモからGoogleユーザーになりすますことはできません。Google Booksキーなどの秘密情報はEdge Function側だけに保存します。画像を取得できなくてもタイトル入りの代替表示で使えます。

## 確認

```powershell
npm test
```

83件のNodeテストに加え、実Supabaseで15件のRLS/制約検証と16件の検索キャッシュ・制限チェックを実行し、検証用の変更をロールバックしています。OAuth・クラウドアダプターの単体テストはSDK差し替えで、実際のGoogle認証成功・二端末同期を確認したことにはなりません。実ブラウザの確認内容は `outputs/verification.md` を参照してください。Edge Functionの再デプロイ前は `npm run package:books-function` を実行します。

検索保護は既存Supabase DBの非公開スキーマを使用します。ログイン済みは200回/24時間、ゲストは60回/24時間、各利用者は30回/分です。同じIPの認証前リクエストにも60回/分の制限があります。Google Booksへの実送信は全体で900回/太平洋時間の日付・40回/分までとし、到達後は補完APIを使用します。検索結果の再利用は提供元のCache-Controlを優先し、最大24時間・250件まで。Googleの現在のprivate/max-age=0応答は共有保存せず、Open Library・NDL等の保存可能な応答を共有します。新しい有料サービス・課金設定は追加していません。詳細は `outputs/catalog-protection.md` を参照してください。

GitHub Pagesは `gh-pages` ブランチのルートから配信します。`reading-prototype.html`・`readtrace*.mjs`（テストを除く）・`readtrace.css`・`assets`・`index.html`・`.nojekyll` をまとめて公開してください。`.env`、サーバー、ログ、ローカル確認用スクリーンショットは配信不要です。
